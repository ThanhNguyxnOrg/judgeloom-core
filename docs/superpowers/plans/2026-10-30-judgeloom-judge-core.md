# JudgeLoom Judge Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working pull-based judge core: versioned problem packages, queued judge jobs, judge-token auth, claim/lease, per-case results, server-authoritative scoring, final verdicts, and WebSocket updates — verified with a fake worker before any real sandbox.

**Architecture:** Django 5.2 LTS is the control plane. Judge workers pull work over HTTPS using a dedicated token; `JudgeJob` rows are claimed with `select_for_update(skip_locked=True)` and protected by leases. `ProblemPackage` is immutable and content-addressed. The server recomputes points/subtask scores from package group definitions; worker-reported finish points are only a cross-check. No user code runs in Django or Celery.

**Tech Stack:** Python 3.12, Django 5.2.18 LTS, Django Ninja, PostgreSQL 16+, Redis 7, Channels 4, pytest-django. Real Go worker/go-judge is the next plan; this plan tests the protocol with a fake worker.

**Spec:** `docs/superpowers/specs/2026-10-30-judgeloom-core-design.md`

## Global Constraints

- Django must be `>=5.2.18,<5.3` for this plan; do not use Django 6.x.
- Production and CI tests must use PostgreSQL. SQLite is allowed only for quick local runs.
- No user code execution in Django, Celery, or test processes in this plan.
- `ProblemPackage` rows are immutable after creation; activation changes only `is_active`.
- Server is authoritative for `Submission.points` and `submission.subtask_scores`; worker `finish.points` is not trusted.
- Claim uses `select_for_update(skip_locked=True)`; lease expiry must requeue or fail a job deterministically.
- Events are published after the transaction commits; consumers use matching group and event type names.
- License: AGPL-3.0-or-later. Do not copy HydroOJ, HustOJ, or Themis code; DMOJ/CMS code only with notices if copied.
- Use `python -m pytest` and `python manage.py` in commands. Commit after each task.

## Review Focus

- Two workers claim the same job under concurrency → exactly one claim wins; the other gets no duplicate.
- Worker retries `cases` or `finish` after a network error → no duplicate score, no duplicate test-case rows.
- Worker dies after claim → lease expiry requeues; after max attempts the submission becomes `IE`, not stuck.
- Package hash mismatch or stale package → worker/API rejects instead of grading wrong data.
- Worker sends inflated `finish.points` → server recomputes and ignores the inflated value.
